# V0.3 产品方向修正案

> **项目：** Oneiro 微信小程序  
> **文档状态：** 已决策 / 待执行  
> **适用范围：** 产品、交互、前端、后端、AI 提示词、分享物料、审核材料  
> **优先级：** 高于《Oneiro V0.2 开发计划》；如两份文档冲突，以本修正案为准  
> **团队约束：** 单人开发、零预算、上线前无真实用户数据

---

## 1. 修正背景

市场可行性审查确认，V0.2 将出生日期、出生时间和出生城市设为获取首梦解读的前置条件，并默认展示命理内容，形成了**漏斗、审核、定位三重致命伤**：它在用户最需要快速记录、最接近首次价值的时刻增加高摩擦表单；使产品实际功能与“不是算命”的定位冲突，并显著提高个人主体的小程序审核风险；同时会把普通梦境记录用户与追求明确预测的玄学用户同时推远。V0.3 不否定已完成的底层技术，而是调整价值交付顺序：先无阻断完成梦境记录与解读，再以自愿、渐进、脱敏的方式加入东方出生节律，并将语音记录、被记得的感受和作品化传播提前。

---

## 2. 五条决策的展开

### 2.1 命理后置：出生资料不得阻断主流程

#### 改什么

1. 删除 `profile_required` 对解读接口的阻断逻辑。出生资料为空、部分填写或城市无法识别时，均应正常生成基础解读。
2. 首梦主流程不出现出生资料表单、补齐弹窗或强制跳转。
3. “我的资料”作为独立入口保留，用户可自愿填写或删除。
4. 未填写资料时，结果页不显示空白占位、锁定模块或“补资料才能解锁”等提示。
5. 用户填写资料后，仅对**之后新生成的解读**增加“出生节律”段落。
6. 历史梦不自动、不免费重新生成。未来提供“用新资料重新解读”入口，作为独立付费候选能力；付费功能上线前不承诺免费回溯。

#### 为什么

首梦阶段需要证明的不是资料完整率，而是用户能否在梦消退前完成记录并得到即时价值。出生资料前置会引发退出、随意填写和中断后不返回，且扩大个人信息收集范围。后置处理同时降低首次漏斗摩擦和审核暴露面。

#### 验收标准

- 新用户不填写任何出生资料，可从打开小程序到获得完整基础解读。
- 任一出生字段缺失或解析失败时，接口不得返回 `profile_required`。
- 无资料结果页不出现“出生节律”段落，也不出现催填占位。
- 新资料保存后仅影响新解读，历史解读内容和版本保持不变。
- 用户可单独删除出生资料；删除后新解读不再使用，历史记录不被改写。
- 自动化回归覆盖“无资料、仅生日、完整资料、删除资料”四条路径。

### 2.2 软性植入：采用东方出生节律表达

#### 改什么

解读结构统一为：

- **70% 梦境叙事：**人物、场景、行动、情绪、冲突及现实联想；
- **20% 文化梦象：**东方文化中的象征性观察，不给固定吉凶；
- **10% 出生背景：**仅在用户自愿提供资料后，以“出生节律”“内在气质底色”等表达呈现。

前端、AI 输出、分享卡及小程序资料全面禁用“四柱、八字、日主、五行、排盘、命理”等显性术语。后端已经完成的确定性计算引擎、城市经纬度解析、真太阳时校正、计算版本记录继续保留，不在用户侧展示技术排盘结果。

资料收集采用渐进方式：

1. “我的资料”先提供一个可跳过的生日字段；
2. 用户至少获得一次解读价值后，再邀请补充出生时间和出生城市；
3. 每次收集均说明用途、是否必填、如何删除；
4. 不因拒绝、跳过或删除而降低基础功能可用性。

#### 为什么

出生背景是辅助理解镜头，不是产品身份，也不是首梦价值成立的前提。保留后端能力可避免已完成开发浪费；收敛用户侧措辞和占比，则能降低审核风险，避免用户以“算得准不准”评价产品。

#### 验收标准

- 有资料解读中，梦境叙事、文化梦象、出生背景的目标篇幅约为 70/20/10，出生背景不得成为标题或结论主体。
- 全仓 UI 文案、提示词、模型输出、导出图片和审核截图中不出现禁用词。
- 输出层增加敏感词扫描；命中后必须重写或降级为无出生背景版本。
- 仅生日时只生成低精度、非确定性的背景表达；资料完整时可调用保留引擎，但前端仍不展示底层术语和计算盘面。
- 资料页明确显示：“用于后续解读中的文化背景参考，可跳过，可随时删除。”
- 分享卡永不携带生日、出生时间、城市、校正时间或可反推出上述资料的文本。

### 2.3 语音输入 P0：实现醒后 15 秒记录

#### 改什么

接入微信官方同声传译插件 WechatSI，在记录页提供按住说话或点击开始/结束的语音转文字能力。转写结果进入可编辑文本框，用户确认后再提交；原始梦文本必须优先保存，AI 解读失败不影响记录留存。

异常处理至少覆盖：拒绝麦克风权限、无网络、插件失败、空转写、转写中断及用户主动取消。任何异常均可立即切换为键盘输入。

#### 为什么

“醒后梦正在消退”是 Oneiro 最明确、最直接的使用场景。相比继续扩展排盘和复杂档案，语音输入能直接缩短首次记录时间，并验证用户是否真的愿意记录梦。

#### 验收标准

- 真机环境可完成“打开记录页—开始说话—生成可编辑文字”，目标中位耗时不超过 15 秒。
- 首次权限被拒后不出现死路，并明确提供“改用文字输入”。
- 转写内容可编辑、追加和清空，不得未经确认直接生成解读。
- AI 调用失败时，已确认文本和创建时间仍被保存。
- 埋点区分文字与语音路径，并记录授权失败率、转写成功率、编辑率和提交率。
- WechatSI 不可用时，文字主流程仍完整可用。

---

### 2.4 长期记忆：先交付三个“被记得”时刻

#### 改什么

V0.3 不先建设完整记忆状态机，而以最小数据结构实现三个可感知时刻：

1. **次日一句现实回访：**梦保存后的次日，在用户再次打开或经用户授权的提醒中询问一句与该梦有关、可跳过的问题。
2. **第二次解读引用已确认线索：**只有用户明确写下或确认过的现实片段，才允许在后续解读中自然引用一条；不得引用模型自行推断的标签。
3. **重复梦象主动点亮：**同一梦象累计再次出现时显示次数，例如“水第 3 次出现在你的梦里”。用户可点开查看对应梦记录，也可纠正合并结果。

`observed / stable / pinned / archived` 完整状态机、复杂权重、四视图档案及 3–5 条综合检索后置冻结。

#### 为什么

护城河不是宣称单次解读更准确，而是用户能够明确感受到“它记得我说过什么，并且没有乱记”。三个时刻比后台数据结构更容易被用户感知，也更适合单人团队验证第二次使用价值。

#### 验收标准

- 次日回访只关联一条具体梦记录，支持回答、跳过和关闭后续回访。
- 第二次解读最多引用一条已确认线索，并提供“为什么这样理解？”入口查看来源。
- 未确认的 AI 推测不得进入后续生成上下文。
- 重复梦象必须关联至少两条独立梦记录；次数可追溯，不允许模型凭空声明。
- 删除梦或现实片段后，相关引用和计数同步失效。
- 完整记忆状态机不得作为 V0.3 上线前置依赖。

### 2.5 设计即传播：分享物必须是作品

#### 改什么

保留靛青蚀刻视觉体系，但分享内容从“私人梦摘要”调整为“旁观者也能理解的作品”。首批只建设两类传播钩子：

- **聚合话题卡：**如“最近反复梦见水的人，在担心什么？”以文化梦象和开放问题引导旁观者记录自己的梦。
- **3 梦解锁原型人格卡：**基于至少 3 个梦中实际重复的场景、行动或情绪，生成阶段性“梦境原型人格”；必须标注“阶段观察，不是永久人格判定”。

传播阵地同时覆盖微信聊天/群分享、朋友圈保存图片和小红书 3:4 首图。

#### 为什么

原梦和现实片段过于私密，直接分享会产生社交成本；完全去除内容又缺乏点击理由。作品化卡片需要在保护隐私的同时，让旁观者看到可参与的话题或可识别的自我表达。

#### 验收标准

- 每张卡必须包含一个无需了解原梦也能理解的标题或问题。
- 不展示原梦正文、现实笔记、出生资料、精确日期、真实姓名和可识别人物关系。
- 3 梦卡仅在存在跨梦证据时生成；无重复证据时不得硬凑人格。
- 导出前提供隐私预览和可见字段开关。
- 微信与小红书版本均通过真机裁切检查，关键信息不得被头像、昵称、按钮或平台裁切遮挡。

## 3. 新的首梦漏斗设计

以下流失为上线前估算区间，仅用于埋点和定位问题，不作为行业基准。

| 步骤 | 用户路径 | 产品要求 | 预期单步流失 |
|---|---|---|---:|
| 1 | 打开小程序 | 首页直接展示“记下刚才的梦”，不弹资料表单 | 5%–10% |
| 2 | 进入记录页 | 默认可文字输入，语音按钮同级可见 | 5%–10% |
| 3 | 开始记录 | 语音授权失败可切文字；允许碎片和短句 | 10%–20% |
| 4 | 确认文本 | 转写可编辑，明确“先保存，再解读” | 5%–10% |
| 5 | 提交并保存 | 先创建梦记录，再调用 AI；不检查出生资料 | 5%–10% |
| 6 | 等待生成 | 显示可退出提示；失败可重试且不丢梦 | 5%–10% |
| 7 | 获得基础解读 | 梦境叙事＋文化梦象；无资料时到此完整结束 | 目标到达率 50%–65% |
| 8 | 首次价值后邀请 | 轻提示“愿意补充生日，让以后多一个出生节律视角吗？” | 可跳过，不计入首梦完成 |
| 9 | 保存、回访或分享 | 用户自主选择，不自动公开 | 不阻断完成状态 |

“首梦完成”定义为：**梦文本已保存且用户成功打开解读结果页**。生日填写率、分享率、继续对话率均不得混入首梦完成率。

## 4. 修订后的 Sprint 优先级

### Sprint V0.3-A：解除阻断与审核收敛，P0

- 删除资料阻断和强制跳转；
- 重构无资料/有资料两种解读模板；
- 完成禁用词清理、输出扫描及资料删除；
- 保留真太阳时与确定性计算代码，但用户侧全面脱敏；
- 真机验证 AI 失败保存和首梦路径。

### Sprint V0.3-B：15 秒语音记录，P0

- 接入 WechatSI；
- 完成权限、失败降级、可编辑转写和语音漏斗埋点；
- 不开发自建语音识别或原始音频长期存储。

### Sprint V0.3-C：三个“被记得”时刻，P1

- 次日现实回访；
- 一条已确认线索的跨梦引用；
- 重复梦象计数、查看与纠正；
- 删除后的关联失效。

### Sprint V0.3-D：作品化传播与种子验证，P1

- 微信 5:4 分享图、小红书 3:4 首图；
- 聚合话题卡、3 梦原型人格卡；
- 招募种子用户，按分层指标观察，不扩展新功能。

### 原 V0.2 逐项处置

| V0.2 项目 | V0.3 处置 |
|---|---|
| 原梦保存、结构化事实、模型版本 | **保留** |

| 禁用词/表达 | 统一替代词 |
|---|---|
| 四柱、八字 | 出生节律、出生背景 |
| 排盘、命盘 | 背景计算、节律参考 |
| 日主 | 内在气质底色 |
| 五行 | 文化意象倾向、象征元素 |
| 命理、命格 | 东方文化视角、气质背景 |
| 真太阳时校正 | 基于出生地点的时间换算；默认不在 UI 展示 |
| 吉凶、运势 | 近期感受、阶段变化 |
| 注定、必然、预示 | 可能让你联想到、也许与……有关 |
| 准不准 | 是否有启发、是否贴近你的感受 |
| 大师解梦、AI 算命 | 梦境记录与文化解读 |

**小程序简介统一建议：**

> 记录醒后的梦，获得基于梦中细节与东方文化梦象的启发式解读，并在长期使用中发现重复出现的个人线索。内容仅供自我观察，不作医疗、关系或未来判断。

该措辞规则同时适用于 UI、AI 输出、客服回复、分享卡、审核截图和应用商店介绍。

## 6. 北极星指标修正

原“14 天内完成 3 梦且认为更懂我”同时受自然梦频、梦回忆率、触达、记录摩擦和解读质量影响，无法判断失败原因。V0.3 改用分层指标，不再以单一混合比例作为北极星。

### 一级北极星：有效记录用户的被记得体验率

**定义：**产生第二次有效记录的用户中，成功触发至少一个“被记得”时刻，并反馈“自然/有帮助”而非“突兀/记错”的比例。

### 分层诊断指标

1. **可达性层：**首页到开始输入率、语音授权率、转写成功率。
2. **首梦价值层：**首梦完成率、解读打开率、“有启发”率、“不贴梦”率。
3. **自然回访层：**次日回访打开率、回答率、关闭率。
4. **复用质量层：**第二次记录人数、确认线索引用成功率、引用纠正率。
5. **模式价值层：**重复梦象点亮率、查看率、误判纠正率。
6. **传播层：**卡片生成率、主动分享率、分享落地访问率、落地后开始记录率。
7. **资料层：**首次价值后生日自愿填写率、补充时间/城市率、资料删除率。

“7 天第二梦”和“14 天三梦”继续观察，但只作为行为结果，不单独判定产品成败；分析时必须区分“期间没有梦”“有梦但没记住”“记住但未使用产品”。

## 7. 传播设计规范

### 7.1 规格

- **微信聊天/群卡：**5:4，建议导出 `1000×800 px`；标题和主体意象位于中央安全区。
- **朋友圈及小红书首图：**3:4，建议导出 `1242×1656 px`。
- 以同一靛青蚀刻母版生成两种裁切，不允许直接拉伸。
- 保留靛青底色、蚀刻线条、有限金色点亮；正文控制在 60 字以内。
- 品牌标识低干扰，卡片主体不得变成二维码广告。小程序码仅用于用户主动保存的导流版本。

### 7.2 钩子类型

1. **开放问题：**“为什么水总在梦里出现？”
2. **重复次数：**“水，第 3 次出现在你的梦里。”
3. **聚合话题：**“最近梦见迟到的人，都在追赶什么？”
4. **阶段原型：**“你的 3 梦原型：夜航者。”必须附“阶段观察”。
5. **审美收藏：**以单一梦象和一句非结论性文字构成作品，不复述私人故事。

### 7.3 隐私边界

默认不进入卡片的内容包括：原梦正文、现实片段、真实姓名、具体关系身份、出生资料、精确时间地点、健康与创伤信息、未成年人信息及用户未确认的 AI 推测。

分享前必须展示最终预览，由用户主动点击生成或保存；不得默认勾选敏感字段，不得以分享换取解读、报告或功能解锁。已分享图片无法远程撤回，应在生成前明确提示。涉及自伤、性暴力、疾病、违法行为或可识别第三人的梦，不提供公共传播模板，仅允许私密保存。

## 8. 生效结论

V0.3 的执行顺序固定为：**解除出生资料阻断与输出脱敏 → 上线 WechatSI 语音记录 → 实现三个“被记得”时刻 → 建设双平台作品化分享 → 进入种子验证。**

在上述闭环获得真实用户证据前，不恢复完整记忆状态机，不扩建 7/15/30 梦报告，不增加星盘、运势或显性命理能力。已完成的确定性计算和真太阳时引擎继续作为后台能力保留，但不得重新成为首梦前置条件或产品对外定位。
